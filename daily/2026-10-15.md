### 一、Agent CPU 侧优化：从 DAG 到高频工具缓存

#### 可见原始提问

1. “调研一下agent CPU侧优化的相关方向，有什么可以做的，按粒度从粗到细，DAG为较粗力度的，高频工具执行缓存之类的有吗”
2. “这些定义有开源的标准吗，各个层级有已存在的工作吗？”

#### 核心知识点

- **优化粒度的分层思路**：粗粒度从 Agent 工作流 DAG、任务依赖、并行与增量执行入手；中粒度关注工具调用的调度、重复请求合并、缓存、进程和运行时复用；细粒度关注序列化、JSON 解析、Python 调用开销、CPU/NUMA 亲和性等。
- **高频工具调用优化**：Tool Result Cache（结果缓存）、Singleflight（并发相同请求去重）、MCP 工具发现或元数据缓存、Warm Runtime（预热执行环境）等，是可进一步验证的方向。缓存必须考虑工具副作用、权限隔离、有效期和失效策略。
- **开源标准与现有工作**：当前检索到的对话结论是，尚无被普遍承认的统一“Agent CPU 优化 L1–L6 标准”。相邻实践分布在 LangGraph、Temporal、Airflow、Bazel、MCP、Ray、Linux cgroups、Kubernetes、OpenTelemetry 等不同层面；这些项目各自覆盖部分问题，不能等同于一套统一分层标准。
- **关键区别**：Agent CPU 侧优化通常关注编排、工具、上下文处理与运行时开销；这不同于 GPU/NPU 算子内核的优化，虽然都需要端到端性能分析。

#### 待深入问题

- 是否能建立一个面向第三方 Agent 纳管场景的可测量分层模型：DAG / Tool / Runtime / Data / OS？
- 哪些工具请求可安全缓存？如何定义 cache key、租户边界、TTL、失效和副作用？
- 对同步串行工具调用、并发工具调用、长链路 Agent 工作流分别如何设计基准？
- Agent 工作流执行中的 CPU 时间、工具等待时间、网络时间、模型推理时间如何拆账？

### 三、Continuous Batching 原理

#### 可见原始提问

1. “Continuous Batching介绍一下这个技术的原理”

#### 核心知识点

- Continuous Batching（连续批处理）与传统静态批处理的关键区别，是推理服务可以在生成过程中动态调整批次成员，而非必须等待一整批请求全部结束。
- 对自回归解码，通常以迭代或 token 生成步骤为调度机会：已完成请求退出，等待请求可加入，从而减少空转、提高设备利用率。
- 其实际效果依赖 KV Cache 容量、Prefill/Decode 组织、调度策略、最大并发与延迟约束，不能只看吞吐量。
- 与 FlagOS 话题的联系：Continuous Batching 主要是推理服务调度层技术；底层算子和编译优化可以改善每一步执行效率，但二者职责不同。

#### 待深入问题

- Iteration-level batching 与请求级静态 batching 的时间线和资源占用差异如何定量表示？
- 与 PagedAttention、chunked prefill、prefill/decode 分离等机制如何配合？
- 在 vLLM/SGLang 中，调度开销、KV Cache 压力和吞吐/尾延迟如何权衡？

### 四、Triton：高性能算子编程与多后端编译

#### 可见原始提问

1. “介绍一下triton”

#### 核心知识点

- 结合当日 FlagOS/算子编译语境，Triton 主要指用于编写高性能 GPU/加速器 Kernel 的编程语言及编译器生态；这与名称相近的 Triton Inference Server 是不同产品。
- 从张量/块级计算表达，经编译器中间表示与目标后端代码生成，映射到硬件线程、访存与指令；不同硬件需要适配后端与专用优化。

#### 核心知识点
