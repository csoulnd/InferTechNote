# 产品调研

先读根 AGENTS.md 和目标目录索引，沿用仓库元数据与导航。调研放在 agent/investigations/products/<product>/，网站展示不属于本技能。

## 分析流程

1. 明确产品名称、供应商、研究范围、查阅日期。先判断它是应用、Harness、框架还是运行平台，避免同名或生态混用。
2. 查官方文档与官方源码。建立 sources.md 来源编号表，记录来源支持的结论。源码分析记录提交 SHA；滚动云文档不能冒充固定版本。
3. 先完成一个产品，再开始下一个。每份至少回答定义、架构、定制、托管责任、限制和待验证事项；可将复杂内容拆为 architecture.md 与 customization-and-hosting.md。
4. 区分文档事实、源码事实、分析推断和未知项。架构重构图明确标为研究视图；未公开的底层组件不根据 SDK、兼容协议或示例框架推定。
5. 按实际部署模式分别列用户与平台责任。配置式 Harness、容器应用和本地纳管的能力不能互相借用。定制分模型、提示词、工具、技能、工作流、代码与执行引擎，不把这些一概称为低代码。
6. 托管分析分别检查身份、隔离、网络、伸缩、版本、观测和恢复。分开会话历史、文件、长期记忆、执行检查点和外部副作用；历史恢复不证明任务自动续跑。
7. 企业能力记录支持条件与责任边界。没有同负载实测，不评判性能、成本或稳定性优劣；待实测项写触发条件和观测目标。
8. 更新邻近索引，保留 Knowledge Extraction 段。完成一个产品后，只把本次发现的可复用纠错规则加入此技能，在系列索引记录迭代缘由。

## 完成检查

检查来源可支持结论、相对链接、单 H1 与 YAML。运行 git diff --check 和仓库知识审计；技能修改后运行 skill-creator 的 quick_validate.py。提交和推送遵循当前用户授权，不由技能自动扩大授权。
