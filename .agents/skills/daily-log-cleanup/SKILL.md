# 每日日志清理

`daily/` 是 Git 中的原始日报交接区。日报保持可追溯，知识增量汇集到一个持续维护的文档；清理后的候选再交给知识沉淀流程。

## 输入、产物与边界

- 原始输入为 `daily/YYYY-MM-DD.md`，只接受严格的日期文件名。该文件的内容不改写。
- 知识增量只使用 `daily/knowledge-increment.md`；按 `## YYYY-MM-DD` 分区，区段必须链接原始日报并记录其 Git blob SHA。不得再创建 `YYYY-MM-DD.increment.md`。
- 用 `daily/.knowledge-distillation-state.json` 保存每个来源的 blob SHA、处理结果和本工作流的 `last_accessed_at`。它是处理台账，不是日报，不计入日报留存上限。
- 仅处理对应北京时间日期。来源不存在、为空、未通过版本判定或出现冲突时，不进行知识清理或沉淀。
- 不把私人日程、寒暄、重复状态、工具调用流水或没有可迁移结论的对话写入知识库。
- 不提交、推送或修改远端，除非当次任务另有明确授权。

## 0. 日报留存管理（任何 `daily/` 写入前）

先维护 `daily/`，再新增日报或改写 `knowledge-increment.md`。留存上限只统计 `daily/YYYY-MM-DD.md`。

1. 先删除无干货的占位日报：正文为空，或正文明确仅表示“无新增对话/无对话记录/占位”，且不含实质性主题、结论、决策、引用或待办。周日无对话产生的占位文件属于此类。不得仅因文件很短而删除。
2. 删除后，日报文件上限为 14 条。若待写入新日报，先确保写入后不超过 14 条；若当前已超限，则先降到 14 条。
3. 仍超限时，按 LRU 删除已经成功处理过的原始日报。LRU 的唯一依据是台账中本工作流维护的 `last_accessed_at`；每次读取某日报时更新它。不要依赖 Windows 文件 atime 或 Git 提交时间。
4. 不删除当前目标日期、未处理日报、来源 SHA 已变化但尚未重新处理的日报。若没有可安全淘汰的已处理日报，则停止并报告，需要人工决定，不得为腾出空间删除未处理内容。
5. 删除属于 Git 工作树变更。只有在已获提交与推送授权时，才将删除同步到远端；否则保留为待提交改动并如实报告。

## 1. 获取与重试

1. 北京时间 01:30 检查 `main/daily/YYYY-MM-DD.md`（前一天）。
2. 文件缺失或为空时，不创建增量或复盘；30 分钟后重试，最多重试 3 次，即 02:00、02:30、03:00。
3. 第四次检查仍不可用时，记录“当日日报缺失”并通知用户；不生成空产物。
4. 文件可用后读取 Git blob SHA：若台账中同日期 SHA 相同且已成功处理，则跳过；若未处理或 SHA 改变，则继续。SHA 改变时替换该日期的增量区段，并复核受影响知识笔记。

## 2. 知识增量

1. 以当天原始日报为唯一输入，不混入其他日期的内容。
2. 在 `daily/knowledge-increment.md` 创建或更新对应 `## YYYY-MM-DD` 区段，写明来源链接和 blob SHA，并归纳主题与关键结论、决策与依据、可复用方法/配置/命令、重要引用、待验证事项。
3. 删除寒暄、重复问答和工具执行噪声。当天没有候选时，在该区段标明“无可复用知识候选”，使跳过决定可审计。
4. 同日来源修订时只替换该日期区段；不得影响其他日期区段或原始日报。

## 3. 清理与复盘

1. 以增量区段为主，按需回读原始日报，区分可复用的机制、设计取舍、故障模式、操作边界、已验证结论与待验证问题。
2. 去除时间线、重复问答和只能解释当天过程的上下文；不要把未验证猜测改写成事实。
3. 当存在可复用内容时，在 `agent/reports/daily-reviews/YYYY-MM-DD.md` 创建或更新精简复盘，保留来源日期、重要结论、证据/适用边界、待验证项和可沉淀候选。
4. 复盘使用仓库要求的 YAML frontmatter，并以相对链接指向 `daily/` 中的原始日报和增量区段。当天没有可复用结论时，不创建空复盘。

## 4. 交接给知识沉淀

对复盘中的每个候选，执行仓库的 [knowledge-distillation](../knowledge-distillation/SKILL.md) skill：

- 先检索 `knowledge/`，优先更新回答同一问题的现有笔记。
- 仅将有明确证据、可脱离当天语境复用的内容更新到 `knowledge/`。
- 在复盘与知识笔记间维护相对链接，并更新最近的 README/MOC（确有必要时）。
- 结论仍在探索时，保留在复盘的待验证项，不创建伪知识条目。

## 5. 验证与报告

在仓库根目录运行：

```bash
git diff --check
python .agents/skills/knowledge-distillation/scripts/audit_knowledge.py
```

交付时报告日报留存动作、来源 blob SHA、是否跳过、更新的增量区段与仓库文件、验证结果，以及故意未沉淀或未删除的内容。
